# Database migrations

Migrations are applied in order using the Drizzle journal in `meta/_journal.json`.

## 0011 UUID conversion

`0011_preserve_data_uuid_keys.sql` converts existing integer primary and foreign
keys to UUIDs without deleting rows. It derives matching deterministic UUIDs for
each parent and its foreign keys, then restores constraints and random UUID
defaults for new rows.

Back up the database before applying this migration. Run it only through
`pnpm db:migrate`; the custom migrator executes each DDL command separately and
prints the exact command if CockroachDB rejects it. Do not use `db:push` for this
conversion because schema push cannot perform the data-preserving key mapping.

## 0001_add_author_slug (hand-written)

`0001_add_author_slug.sql` was written by hand (not generated by
`drizzle-kit generate`) because it backfills existing rows in three safe steps:

1. add `authors.slug` as nullable,
2. backfill it from `name_fr` (accents folded, deduplicated),
3. enforce `NOT NULL` + `UNIQUE`.

The schema source of truth is `server/db/schema/authors.ts`, which already
declares `slug` as `text().notNull().unique()`.

### Keeping Drizzle's snapshot in sync

The `meta/0001_*` snapshot for this step is intentionally not committed by hand.
Before generating the next migration, run:

```bash
pnpm drizzle-kit generate
```

Drizzle will diff the schema against the latest snapshot and reconcile state. If
it reports the `authors.slug` column/constraint as already applied, accept the
no-op so the snapshot catches up. This avoids shipping a hand-edited snapshot
that could drift from the generator's output.
