# GuelmaHistory Admin — Flutter Android & iOS Roadmap

## Project Goal

Build a polished, secure, production-ready **GuelmaHistory Admin mobile application using Flutter**, developed in Android Studio and targeting:

- Android
- iOS
- Tablets
- Large-screen/foldable devices where practical

The application will allow authorized GuelmaHistory administrators, editors, authors, and moderators to manage the website from a dedicated native-feeling mobile application.

The app should feel like a professional **mobile editorial CMS**, not like a website squeezed into a mobile screen.

---

# Core Technology Direction

Use:

```text
Flutter
   │
   ├── Android App
   └── iOS App
          │
          ▼
   GuelmaHistory API
          │
    ┌─────┴─────┐
    ▼           ▼
Database    Media Storage
          │
          ▼
    GuelmaHistory.com
```

## Important Architecture Rule

The Flutter application should **NOT connect directly to the production database**.

Use:

```text
Flutter App
     ↓
HTTPS
     ↓
Authenticated API
     ↓
Backend
     ↓
Database / Storage
```

All sensitive authorization and validation must happen on the server.

# PHASE 17 — Offline Draft Protection

At minimum, unfinished article text should survive temporary connectivity loss.

Implement:

```text
Editor
   ↓
Local draft
   ↓
Network available?
   ├── YES → synchronize
   └── NO  → keep local
```

When connectivity returns:

```text
Local changes detected

[Review]
[Sync]
```

Do not silently overwrite newer server content.

# Instructions for the AI Coding Agent

## 1. Inspect Before Coding

Before modifying a feature:

1. Inspect existing related files.
2. Understand existing architecture.
3. Understand the API.
4. Understand data models.
5. Identify reusable components.
6. Create an implementation plan.
7. Then code.

Never blindly generate large amounts of Flutter code.

---

## 2. Work One Milestone at a Time

Do not attempt 50 phases simultaneously.

Complete:

```text
Implement
   ↓
Analyze
   ↓
Test
   ↓
Fix
   ↓
Polish
   ↓
Commit
   ↓
Next feature
```

---

## 3. Never Sacrifice Existing Functionality

After each significant change:

```text
flutter analyze
flutter test
```

Then manually verify the affected workflow.

Fix regressions before moving forward.

---

## 4. No Fake Implementations

Do not pretend features work.

Never use permanent:

```text
Future.delayed(...)
```

to simulate APIs.

Never generate fake analytics and present them as real.

Never mark uploads successful before server confirmation.

Never silently replace real APIs with mock data.

Mocks are acceptable only in clearly isolated development/tests.

---

## 5. Keep Widgets Manageable

Avoid enormous screen widgets.

Prefer:

```text
ArticleEditorScreen
├── ArticleTitleSection
├── EditorToolbar
├── ArticleBodyEditor
├── SaveStatus
└── ArticleSettings
```

But do not create dozens of meaningless one-line widgets merely to increase abstraction.

---

## 6. Protect Content Above Everything

This application manages historical research and potentially irreplaceable writing.

Prioritize:

```text
DATA SAFETY
    >
CORRECTNESS
    >
SECURITY
    >
USABILITY
    >
PERFORMANCE
    >
VISUAL POLISH
```

Never risk article or archival-data loss for a smoother animation or simpler implementation.
